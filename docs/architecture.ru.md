# Архитектура и threat model

## Границы доверия

1. **Доверенный локальный процесс:** парсинг, LM Studio, детерминированная замена, mapping, release gate и восстановление.
2. **Недоверенный документ:** внутри может быть prompt injection. Текст передаётся как данные и не может обойти детерминированную проверку подстрок.
3. **Недоверенное облако:** получает только разрешённые обезличенные поля. Ответ обязан сохранить точные токены операции.
4. **Локальный оператор:** сам включает облачный ключ и видит фактический dry-run payload.

Mapping — словарь в памяти Python с случайным восьмизначным hex nonce. Одинаковое точное значение использует один токен в рамках операции. Замены идут от самой длинной подстроки, чтобы вложенный фрагмент не разрушил более длинный. Код приложения не сериализует mapping.

## Fail-closed политика

| Сбой | Результат |
|---|---|
| LM Studio недоступна/timeout | `BLOCKED`, облачного вызова нет |
| Невалидная schema или выдуманное значение | `BLOCKED` |
| Остаточный явный секрет | `BLOCKED` |
| Не найдено ни одной сущности | Блокировка до ручной проверки |
| Во входе уже есть reserved token | `BLOCKED` |
| Облако изменило/подделало токен | Ответ блокируется, mapping уничтожается |
| Ошибка/timeout облака | Ошибка наружу, mapping уничтожается |

## Поток данных

`instructions` и `input_text` анализируются вместе, затем заменяются как два поля с одной mapping. Показанные UI/API sanitized-поля — именно данные для облака. Системная инструкция `PRESERVE_TOKENS` добавляется после замены и не содержит исходных данных.

## Учтённые угрозы

Пропуск email/телефона/карты/ключа; галлюцинация или битый JSON локальной модели; prompt injection; коллизия с готовым PII-токеном; подделка токена облаком; слишком долго живущая mapping; сырые данные в обычных логах.

## Вне V1

Абсолютная деидентификация, OCR, изображения/аудио, антивирус, шифрованное хранение, multi-user auth, регуляторная сертификация и защита от привилегированного локального атакующего.
