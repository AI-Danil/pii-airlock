# Протокол независимой человеческой проверки

Статус: инфраструктура готова; независимая разметка и метрики по ней ещё не получены.

## Зачем это нужно

Опубликованный fixture-oracle создавался вместе с синтетическими кейсами. Он полезен для регрессии, но не является независимым доказательством. Этот протокол формирует отдельный набор без меток и исходных ID, принимает точные сущности от второго человека и считает качество модели только после фиксации разметки.

## Порядок

1. Создать bundle с новой конфиденциальной солью. Не передавать рецензенту репозиторий, соль, fixture-файл и benchmark.
2. Передать только `blind-items.jsonl`, `review-template.jsonl`, этот протокол и определения типов сущностей.
3. Рецензент записывает точные подстроки исходника и их типы. Чистые кейсы остаются в файле с пустым массивом `entities`.
4. Зафиксировать и захешировать готовую разметку до запуска или показа предсказаний моделей.
5. Посчитать результат через `scripts/score_human_review.py` и сохранить полный per-case отчёт.
6. Для разногласий и любого автоматического допуска документов высокого риска нужен второй рецензент.

## Заранее заданная release policy

- runtime gate не должен пропустить ни одного размеченного чувствительного значения;
- нижняя граница 95% Wilson-интервала общего entity recall должна быть не ниже 0,95;
- для `PASSPORT`, `TAX_ID`, `CARD`, `API_KEY` и `OTHER_SECRET` нужен наблюдаемый recall 1,0 минимум на 20 независимо размеченных примерах каждого типа;
- ошибка модели или schema считается блокировкой, а не пропущенным кейсом;
- fixture-assisted проекция не засчитывается как человеческая проверка.

Текущий набор из 52 кейсов — пилот. В нём нет 20 примеров каждого высокорискового типа, поэтому он не может удовлетворить release policy даже после идеальной разметки.

Команды совпадают с английской версией протокола. Пустой шаблон нельзя интерпретировать как результат. Пока второй человек не закончил разметку, единственный честный статус — `not_collected`.
