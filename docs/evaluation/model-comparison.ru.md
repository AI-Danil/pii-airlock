# Сравнение локальных детекторов

Дата запуска: 22 июля 2026 года. Набор: 52 синтетических документа (`26 ru + 26 en`), в том числе 6 чистых контрольных и 20 adversarial-кейсов. Endpoint: LM Studio `chat/completions`; temperature `0`; включена JSON schema. Облачный провайдер не вызывался. Прогон выполнен в рабочем режиме `opaque` (отдельный токен на каждое вхождение); он измеряет detection и детерминированную замену, а не качество ответа провайдера. Повтор на тех же фикстурах в режиме `typed` дал те же значения детекции: режим токенов меняет вид подстановки, а не результат поиска. Время относится к одному локальному компьютеру и установленным сборкам моделей, поэтому переносить его на другое окружение нельзя.

Прежний прогон на 30 кейсах не является сопоставимым baseline. Новый набор расширен; кроме того, исправлены четыре oracle-значения, которых не было в исходниках как точных подстрок.

## Как читать результат

Qwen нашёл больше размеченных сущностей в целом, но 11 раз предложил значение, не совпавшее с точной подстрокой входа. Гибридный путь сохранил найденные правилами spans для просмотра; автоматическое завершение оставалось заблокированным до подтверждения или правки человеком. Gemma во всех кейсах вернула валидный structured output, однако девять payload, прошедших runtime gate, всё ещё содержали размеченное значение. После зависания прежнего локального runtime Qwen был явно загружен с context 4096, одним prediction slot и выключенным speculative MTP; benchmark использовал timeout 30 секунд на кейс. Затем Gemma загрузили с теми же настройками. В опубликованном результате нет кейсов, завершившихся timeout.

Fixture-oracle остановил эти девять payload, потому что знал ожидаемые ответы. В произвольном документе такой проверки нет. `Проекция review по fixture-разметке` идёт ещё дальше: benchmark применяет эталонные spans и повторяет gate. Это проверка детерминированного контура при идеальной разметке, а не измеренный результат работы человека. Отдельный слепой bundle и scoring protocol подготовлены, но независимая разметка ещё не собрана; статус human review — `not_collected`.

Метрики по типам показывают разные провалы. Recall Qwen: 0,75 для `PERSON`, 0,6667 для `ADDRESS`, 0,5 для `ORG` и 0,5 для `OTHER_SECRET`. Recall Gemma: 0,4375 для `PERSON`, 0,5 для `ORG` и 0,3333 для `TAX_ID`. На размеченных телефонах и email обе модели получили recall 1,0, но небольшой синтетический срез не доказывает общего покрытия.

Сборка Qwen помещала ограниченный schema JSON в `reasoning_content`, оставляя `content` пустым. Compatibility-path разбирает этот JSON и всё равно применяет проверки enum, точных spans и gate. Обе модели остаются экспериментальными; ни один результат не оправдывает автоматическую работу с документами высокого риска.

Машиночитаемые результаты: [`live-combined.json`](live-combined.json). Команда повтора:

```bash
pii-airlock benchmark --models qwen,gemma --timeout 30 --token-mode typed --output docs/evaluation/live-combined.json
```

Повторные запуски могут различаться даже при temperature `0`. Сборка модели и железо также влияют на распознавание и время.
