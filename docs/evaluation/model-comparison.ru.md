# Живое сравнение моделей

Дата: 2026-07-20. Железо и конфигурация LM Studio относятся к локальной машине автора; это не сравнение производительности разных устройств. Набор: 30 синтетических кейсов (`15 ru + 15 en`). Temperature: `0`. LM Studio `chat/completions` с JSON schema. Облако не вызывалось.

| Метрика | Qwen 3.5 9B | Gemma 4 E4B |
|---|---:|---:|
| Разрешённые cloud payload / 30 | 25 | 25 |
| Контрольные секреты в разрешённых payload | 0 | 0 |
| Entity-level recall | 0.6667 | 0.7593 |
| Лишние значения для замены | 5 | 4 |
| Schema/exact-substring ошибки | 4 | 0 |
| Runtime gate failures | 0 | 0 |
| Блокировки dataset release gate | 1 | 5 |
| Успешный round-trip | 26 | 30 |
| Медиана времени кейса | 2.556 с | 1.567 с |
| Максимум | 6.182 с | 4.116 с |

Обе модели помечены **экспериментальными**. Ноль утечек в разрешённых payload означает, что fixture oracle не допустил в облако payload с известным ожидаемым значением; это не гарантия для неизвестных документов. Для текущей reasoning-сборки Qwen понадобилась совместимость: schema-JSON приходил в `reasoning_content` при пустом `content`. Он всё равно проходит JSON/enum/exact-substring проверки.

Данные каждого кейса: [`qwen.json`](qwen.json), [`gemma.json`](gemma.json). Повтор: `pii-airlock benchmark --models qwen,gemma`; модельные сборки и железо могут изменить результат.
