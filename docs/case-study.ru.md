# Кейс: локальная псевдонимизация перед облачным запросом

## Контекст

Личный ассистент может отправлять провайдеру и свои инструкции, и документ. В обоих полях бывают имена, контакты, адреса, идентификаторы и ключи. Задача этого проекта уже: проверить, может ли локальный контур убрать найденные значения, показать подготовленные исходящие поля и восстановить только значения текущего запроса.

## Реализация

LM Studio предлагает точные чувствительные подстроки в structured JSON. Python проверяет каждое значение, отдельно в каждом поле выбирает непересекающиеся spans от длинных к коротким и создаёт токены только для фактически заменённых значений. Второй детектор ищет в результате несколько формализованных типов данных. Mapping остаётся в памяти процесса и удаляется после завершения, ошибки, блокировки, явного delete или одним активным TTL-очистителем через десять минут.

Web UI останавливается на статусе `READY_FOR_REVIEW` и локально подсвечивает исходные spans по metadata без исходных значений. Без ключа провайдера завершение работает как dry-run. Если OpenAI настроен, ответ считается недоверенным: любой неизвестный или изменённый фрагмент `__PII_` блокирует восстановление. Completion атомарно забирается до вызова провайдера. Web-записи требуют приватную session-cookie и same-origin, маршрут Гоши — bearer-токен.

## Материалы проверки

- 30 синтетических документов: 15 русских и 15 английских;
- две установленные локальные модели: `qwen/qwen3.5-9b` и `google/gemma-4-e4b`;
- 64 offline-теста span-based замены, одноразового completion, активного TTL, capacity, cookie/bearer auth, Host/Origin, лимитов body и файлов, токенов, логов и stub-сценариев;
- JSON по каждому кейсу со статусом и временем;
- скриншот Web UI, описание архитектуры, ограничения безопасности и выключенный адаптер Гоши.

В fixtures нет реальных персональных данных и рабочих ключей. Облачный провайдер во время benchmark не вызывался.

## Результат опубликованного запуска

| Метрика | Qwen | Gemma |
|---|---:|---:|
| Entity recall | 0,7037 | 0,7593 |
| Ошибки детектора | 4 | 0 |
| Проходы runtime gate | 23 | 26 |
| Кейсы с контрольным значением после runtime gate | 0 | 4 |
| Проходы fixture-oracle | 23 | 22 |
| Медиана времени | 2,617 с | 1,355 с |

Главный результат — не ноль известных значений после oracle. В этом прогоне runtime gate поймал размеченные значения Qwen, но пропустил четыре кейса Gemma. Fixture-oracle остановил их, потому что знал ожидаемые ответы; у произвольного документа такой проверки нет.

Четыре ошибки Qwen — значения, которые не совпали с точной подстрокой входа. Они заблокированы до замены. Невалидного JSON/schema в этом запуске не было. У Gemma выше recall и ниже медиана времени, но через runtime gate прошли четыре известных контрольных значения.

## Решение

Проект годится как демонстрация и инструмент просмотра в dry-run. Он пока не должен автоматически разрешать облачные запросы для документов высокого риска. Интеграция с Гошей остаётся выключенной. Следующая отдельная итерация должна заняться recall: ансамблем, ручной коррекцией spans, расширенным синтетическим набором и метриками по типам. Более уверенная формулировка в интерфейсе измеренный разрыв не исправит.
