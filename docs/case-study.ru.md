# Кейс: локальный privacy-gate перед облачным запросом

## Узкая задача

Личный ассистент может отправлять провайдеру и формулировку задачи, и документ. В обоих полях бывают имена, контакты, идентификаторы, адреса и ключи. Проект проверяет один ограниченный сценарий: может ли локальный процесс заменить выбранные spans, показать точный исходящий запрос и восстановить только значения текущей операции.

Это не заявление об анонимизации произвольных документов. В benchmark остались размеченные значения, которые проходят реализованный runtime gate.

## Что реализовано

Детерминированные правила и LM Studio предлагают spans. Правила нормализуют несколько Unicode- и zero-width-обфускаций, сохраняя связь с точными offsets исходника. Вывод модели обязан использовать разрешённые типы и буквальные подстроки входа. Python разрешает пересечения от длинных spans к коротким, создаёт случайные токены текущей операции только для реально использованных участков и запускает остаточный scan. Теперь default — `opaque`: каждое вхождение получает отдельный токен без типа сущности. Связываемый `typed` остаётся только для диагностики.

Web UI показывает metadata spans без исходных значений и позволяет добавить, удалить или сменить тип точного выделения. При семантической ошибке модели детерминированные находки сохраняются, но completion заблокирован до подтверждения. Prompt-подобный текст показывается как предупреждение; автоматический stateless-маршрут его блокирует. В инструкции провайдера задача и документ отделены как недоверенный контент, который нельзя исполнять как команду.

Mapping живёт только в памяти процесса. Активный очиститель удаляет операции через десять минут, store ограничен 100 ожидающими операциями, а completion атомарно забирает операцию до обращения к провайдеру. Это at-most-once: не более одной попытки, без гарантированной доставки и автоматического повтора. DOCX и PDF разбираются в короткоживущих процессах с лимитами времени, размера, распаковки, страниц и объектов. Manifest фиксирует охваченные области и реальную изоляцию; скрытые и активные неподдерживаемые части отклоняются. На macOS worker входит в системный sandbox, если он доступен. На других платформах более слабая граница указана явно.

Ответ облака остаётся недоверенным. Неизвестные, изменённые, неполные и лишний раз повторённые PII-токены блокируют восстановление. Восстановить можно только точные токены забранной операции. Восстановленный текст несёт taint-policy: инструменты, запись, внешние сообщения и финансовые действия требуют подтверждения пользователя. Completion также возвращает подписанный PII-free receipt; он подтверждает целостность под одним ключом, а не качество review.

## Доказательные материалы

- 52 синтетических документа: 26 русских и 26 английских; 6 чистых контрольных и 20 adversarial-кейсов;
- живые локальные прогоны `qwen/qwen3.5-9b` и `google/gemma-4-e4b` без облачных запросов;
- 96 offline-тестов замены, ручных правок, Unicode-обфускации, prompt boundary, лимитов и fuzz-входов парсеров, at-most-once completion, TTL, авторизации, token audit, receipts, логов и stub round trip;
- runtime-, dev- и security-tool зависимости с hashes, high-confidence scan секретов, dependency audit, CycloneDX SBOM workflow, release-attestation workflow и обязательные проверки защищённого `main`;
- отделённый blind-review bundle и заранее заданные thresholds со статусом `not_collected`: независимый рецензент ещё не вернул разметку;
- выключенный fail-closed адаптер Гоши с bearer-аутентификацией, обязательными token audit и untrusted-output policy, а также подтверждением перед внешними действиями.

В fixtures нет реальных персональных данных и рабочих ключей. Старые числа на 30 кейсах несопоставимы: набор изменён, а четыре неверных oracle-span исправлены. Опубликованный прогон выполнен в рабочем режиме `opaque` и не обращался в облако; повтор в `typed` дал те же значения детекции. Прогон измеряет детектор, а не качество облачного ответа.

## Живой результат, 22 июля 2026 года

| Метрика | Qwen | Gemma |
|---|---:|---:|
| Entity recall | 0,8472 | 0,8056 |
| Entity precision | 0,8243 | 0,9062 |
| Ошибки детектора | 11 | 0 |
| Проходы runtime gate | 32 | 42 |
| Кейсы с контрольным значением после runtime gate | 0 | 9 |
| Проходы fixture-oracle | 32 | 33 |
| Проекция review по fixture-разметке | 42 | 42 |
| Чистые кейсы без срабатываний | 6 / 6 | 6 / 6 |
| Медиана времени | 2,039 с | 0,492 с |

Все 11 ошибок Qwen были предложениями вне точной подстроки. Детерминированные находки сохранились для review, но автоматический путь остался заблокирован. У Gemma не было schema-ошибок, однако девять размеченных значений прошли runtime gate. Fixture-oracle остановил их потому, что знал разметку; у реального документа её нет.

Проекция review тоже синтетическая: она применяет fixture-разметку как ручные spans. Это проверка детерминированного пути при идеальных правках, а не скорость или точность человека.

## Решение

PII Airlock годится как прозрачная демонстрация и инструмент dry-run review. Он не доказывает безопасность автоматических облачных запросов для документов высокого риска. Обе локальные модели остаются экспериментальными, feature flag Гоши — выключенным. Следующее доказательство уже определено: независимый рецензент должен завершить слепой набор и пройти заранее заданные thresholds. До этого human-result остаётся `not_collected`.
